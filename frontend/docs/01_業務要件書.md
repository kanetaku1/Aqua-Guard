# 業務要件書

## Business Requirements Document (BRD)

## 1. 目的

本書は、AquaGuardにおける業務上の目的、管理対象、Roleごとの責任範囲、および必要な業務を定義する。

本書は「02_ユーザー権限定義書」を基準とする。

画面構成、UI/UX、データベース構造の詳細仕様は本書では定義しない。

---

## 1.1 フロントエンド設計の文書体系

`frontend/docs/` の文書は以下の順に読む。上位の文書が下位の文書の前提になる。

| # | 文書 | 定義すること |
| --- | --- | --- |
| 01 | 業務要件書（本書） | 業務の目的・対象・Roleごとの業務・対象外 |
| 02 | ユーザー権限定義書 | Role・権限・情報アクセス範囲 |
| 03 | 用語定義 | 業務用語・状態・値の種類 |
| 04 | KPI・データ項目定義書 | KPIの計算式と集計ルール、水質項目の単位・閾値、状態の判定ルール |
| 05 | 画面・機能要件書 | 画面構成・遷移・画面ごとの表示内容と機能 |
| 06 | 画面構成ツリー | 全画面の「画面 → セクション → 部品 → 状態違い」の構造（ワイヤーフレーム） |
| 07 | UI・UX設計書 | 色・サイズ・部品を使う判断基準、UXルール、品質基準 |
| 08 | デザインシステム定義書 | 色・書体・アイコン・部品の確定値と実装クラス |

- 文書間で矛盾がある場合は、番号の小さい文書（業務・権限）を正とし、下位の文書を修正する。
- 実装（`frontend/prototype/`）は 05〜08 に従う。仕様を変える場合は文書を先に更新する。
- `en/` は英語版（別途作成）。

## 2. 業務対象

システムでは、以下の階層で養殖業務を管理する。

```text
Company
 ├── Farm A
 │    ├── Pond 01
 │    └── Pond 02
 ├── Farm B
 │    ├── Pond 01
 │    └── Pond 02
 └── Farm C
      ├── Pond 01
      └── Pond 02
```

- **Company**：複数Farmを管理する単位
- **Farm**：複数Pondから構成される養殖管理単位
- **Pond**：エビ養殖を行う現場単位

---

# 3. Roleと業務責任

| Role | 管理単位 | 業務上の姿勢 |
| --- | --- | --- |
| Farms Manager | Company配下の全Farm | 把握する（VIEW / UNDERSTAND） |
| Technical Manager | 担当Farm内のPond | 監視・調査・管理する（MONITOR / INVESTIGATE / MANAGE） |
| System Administrator | システム全体の設定 | 設定・管理する（CONFIGURE / ADMINISTER）。養殖の業務データは扱わない |

## 3.1 Farms Manager

Farms Managerは、Companyが管理する複数Farmを対象として、**Farm全体の状態と生産状況を把握し、必要な問題をTechnical Managerへフォローアップする**。

主な業務：

- 複数Farmの状態を把握する
- Farmの環境状態を把握する
- Pondの異常・傾向をFarm全体の状態を理解するために確認する
- Technical Managerから提出されたDaily / Weekly Reportを確認する
- Farm全体のProduction Statusを確認する
- Farmに発生している問題・異常を把握する
- 必要に応じてTechnical Managerへ確認・追加対応を依頼する

Farms Managerは、Pondの現場運用やActuator操作を直接行わない。

---

## 3.2 Technical Manager

Technical Managerは、担当Farm内のPondを対象として、**Pondの環境および日常的な養殖運用を管理する**。

主な業務：

- Pondの環境状態を監視する
- IoTによる水質情報を確認する
- Pond Alertを確認し、必要な対応を行い、対応内容を記録して解決する
- Pondの技術的・運用上の判断を行う
- Feedingを記録・管理する
- Mortalityを記録・管理する
- Samplingを記録・管理する
- 必要に応じてActuatorを操作する
- Daily Reportを作成する
- Weekly Reportを作成する

---

## 3.3 System Administrator

System Administratorは、**システムを利用できる状態に保つための設定・管理**を行う。養殖の業務データ（水質、生産、Report）は閲覧・操作しない。

主な業務：

- ユーザーを招待・無効化し、Roleと担当Farmを割り当てる
- Farm・Pondを登録し、センサー・Actuatorを割り当てる
- 水質の閾値、目標成長曲線、Reportの提出期限などの運用ルールを設定する

---

# 4. Farms Managerの業務要件

## BR-FM-001 Farm状態の把握

Farms Managerは、Companyが管理する各Farmの状態を把握できなければならない。

Farm状態は、以下の情報をもとに把握する。

- Farmの環境状態
- Pondの異常・傾向（Alertから直接）
- Technical ManagerからのReports
- Production Status

Pondの異常・傾向は、センサーデータから判定されたAlertをもとに直接把握する。Reportの提出を待たない。

Farms ManagerはRaw Sensor Dataを常時監視するのではなく、Farm全体の状態を把握するために必要な情報を確認する。

---

## BR-FM-002 Pond状態の把握

Farms Managerは、Farm全体の状態を理解するため、担当Farm内のPondに発生している重要な異常・傾向を確認できなければならない。

確認対象には以下を含む。

- 異常が発生しているPond
- 異常の種類
- Severity
- 異常の継続状況
- 異常の傾向
- 対応状況（Technical Managerの対応状態・実施した対応）と、継続中 / 解決済み
- Farm状態への関連情報

Farms ManagerはAlertを閲覧のみ行う（Acknowledge / Resolve はしない）。

Farms ManagerはPondの詳細なセンサー監視や現場対応を行わない。

---

## BR-FM-003 Daily / Weekly Reportの確認

Farms Managerは、Technical Managerが作成したDaily ReportおよびWeekly Reportを確認できなければならない。

Reportsは、Technical Managerの運用業務（何が起き、何を観察し、何をしたか）とProduction Statusを把握するための業務情報として利用する。「今何が起きているか」はReportではなくAlert・Environmental / Pond Trendで把握する（§8）。

---

## BR-FM-004 Production Statusの確認

Farms Managerは、各FarmのProduction Statusを確認できなければならない。

Production Statusは、Farm、およびFarmが抱える各Pondのエビの成長具合を把握するために使用する。

主な情報には以下を含む。

- Biomass
- ABW
- ADG
- Survival Rate
- FCR
- 成長目標に対する進み具合（Growth vs target）

Pondごとに放養日が異なるため、生産KPIはPond単位で算出する。Farm・Company単位で表示するのは、合計または重み付きで意味を持つ値に限る（算出・集計ルールは「04_KPI・データ項目定義書」）。

Farms Managerは、Pondごとの生産KPIのサマリー（Pond Production Summary）を閲覧できる。個々の給餌・死亡・サンプリングの記録と、その登録・修正はTechnical Managerの責任範囲とする。

---

## BR-FM-005 Farm Risk / Issueの把握

Farms Managerは、Farm全体として管理上注意が必要な問題・異常を把握できなければならない。

Risk / Issueには、例えば以下を含む。

- 継続する環境上の問題
- 複数Pondに関連する問題
- 生産状況に影響する問題
- Technical Managerから報告された重要な問題

Risk / Issueは、単一のPond Alertそのものではなく、Farm全体の管理上確認する必要がある問題を対象とする。環境上の問題はAlertから直接（Reportを介さず）表示する。

---

## BR-FM-006 Technical ManagerへのFollow-up

Farms Managerは、Farmの状態やReportsを確認した結果、必要に応じてTechnical Managerへ確認・追加対応を依頼できなければならない。

Follow-upの例：

- 状況の追加確認を依頼する
- 詳細な報告を依頼する
- 継続的な監視を依頼する
- 発生している問題について確認する

Farms Manager自身がPondの技術的操作を行うことはない。

Follow-upは**システム外**（電話・メッセージアプリ等の既存の連絡手段）で行う。本システムは、Follow-upの判断材料（Farm Status、Risk / Issue、Production Status、Reports）を提供する。依頼・回答の記録や通知の機能は持たない。依頼を受けたTechnical Managerの対応は、通常どおりAlert対応の記録やDaily / Weekly Reportに残る。

---

# 5. Technical Managerの業務要件

## BR-TM-001 Pond環境監視

Technical Managerは、担当Farm内のPondの環境状態を監視できなければならない。

対象となるIoT情報：

- DO
- pH
- Water Temperature
- TDS
- Turbidity
- Water Level

IoT情報は**3〜5分ごと**に収集し、Reportとは独立してSensor Databaseに保存する。

---

## BR-TM-002 Pond Alert対応

Technical Managerは、Pondで発生したAlertを確認し、必要な技術的・運用上の対応を行う。

- Alertは、Sensor Databaseのデータを閾値（Alert rule）で判定して自動で発報する。Reportの作成・提出はAlertの前提ではない。
- 対応の流れ：Alertを確認（Acknowledge）→ センサー時系列を確認 → 対応 → 対応を記録（時刻・対応種別・メモ）→ 回復を監視 → 解決（Resolve）。
- 記録した対応は、その日のDaily Reportの「Actions Taken」に自動で反映する。

---

## BR-TM-003 Pond運用管理

Technical Managerは、日常的な養殖運用に関する情報を管理する。

対象：

- Feeding
- Mortality
- Sampling

---

## BR-TM-004 Actuator管理

Technical Managerは、必要に応じてPondのActuatorを操作する。

Actuator操作はTechnical Managerの責任範囲とする。

---

## BR-TM-005 Daily Report

Technical Managerは、担当FarmのDaily Reportを作成し、「その日に運用上何が起き、Technical Managerが何を観察し、何をしたか」を報告する（給餌・死亡・健康状態・天候・設備・その日のAlertと対応・所見）。

Daily Reportにはセンサー値を手入力・転記しない。水質はSensor Databaseに保存され、Reportはその日のAlert・センサーデータを参照（リンク）するのみとする。

---

## BR-TM-006 Weekly Report

Technical Managerは、担当FarmのWeekly Reportを作成し、「その週にFarmがどう進んだか」（生産状況・水質の傾向・検査結果・主要な問題と対応）を報告する。Daily Reportの7日分の再掲ではない。

水質の傾向はSensor Databaseから週次で自動集計し、Technical Managerは必要に応じてコメントを加える。

---

# 5A. System Administratorの業務要件

## BR-AD-001 ユーザー・権限の管理

System Administratorは、ユーザーを招待し、Role（Farms Manager / Technical Manager / System Administrator）と担当Farmを割り当て、不要になったユーザーを無効化できなければならない。

- Technical Managerには担当Farmを1つ割り当てる。
- Farms ManagerはCompany配下の全Farmを対象とする。
- ユーザーの削除は行わず、無効化する（記録の作成者を残すため）。

## BR-AD-002 Farm・Pond・機器のマスタ管理

System Administratorは、Farm・Pondを登録・更新し、IoTセンサーとActuatorをPondに割り当てられなければならない。放養・給餌などの養殖の記録はTechnical Managerが扱い、マスタ管理には含めない。

## BR-AD-003 運用ルールの設定

System Administratorは、次の運用ルールを設定できなければならない。設定値は「04_KPI・データ項目定義書」で定義する判定に使われる。

- 水質項目の閾値（全Farm共通の初期値と、Farmごとの上書き）
- 目標成長曲線（DOCごとの目標ABW、On trackとみなす幅）
- Reportの提出期限、データ鮮度の判定時間、Farm Production Statusの判定の境界値

## BR-COM-001 ログイン

すべてのユーザーは、メールアドレスとパスワードでログインし、Roleに応じた画面を利用する。初回は招待メールからパスワードを設定し、忘れた場合は再設定できる。

# 6. Role間の業務フロー

Alert（センサー → 検知）とReport（運用業務の記録）は独立した2つの流れとする。ReportはAlertの前提ではない。

```text
┌──────────────────────┐        ┌──────────────────────┐
│   IoT Sensors        │        │   Technical Manager  │
│   (every 3–5 min)    │        │                      │
└──────────┬───────────┘        │ Pond Operations      │
           ↓                    │ Feeding / Mortality  │
   Sensor Database              │ Sampling / Health    │
           ↓                    │ Alert Response       │
   Alert rules / Thresholds     └──────────┬───────────┘
           ↓                               ↓
   Alert ──→ Technical Manager      Daily / Weekly Report
     │        (Respond)                    │
     ↓                                     ↓
┌──────────────────────────────────────────────────────┐
│                    Farms Manager                     │
│                                                      │
│ Farm Status · Risk / Issue（Alertから直接）           │
│ Production Status · Reports（Review）                 │
└──────────────────────────┬───────────────────────────┘
                           ↓
                 Technical Manager
                     Follow-up（システム外）
```

# 7. 業務責任の境界

| 業務                       | Farms Manager  | Technical Manager |
| -------------------------- | -------------- | ----------------- |
| Farm全体の状態把握         | ●              | ○                 |
| Pond環境監視               | ○ 集約情報のみ | ●                 |
| Raw Sensor Data確認        | -              | ●                 |
| Pond Alert閲覧（Risk / Issue） | ○ 閲覧のみ   | ●                 |
| Pond Alert対応（確認・対応の記録・解決） | -   | ●                 |
| Feeding管理                | -              | ●                 |
| Mortality管理              | -              | ●                 |
| Sampling管理               | -              | ●                 |
| Actuator操作               | -              | ●                 |
| Daily Report               | View           | Create            |
| Weekly Report              | View           | Create            |
| Farm Production Status     | ●              | ○                 |
| Pond Production Summary（Pond別の生産KPI） | View | Manage |
| Farm Risk / Issue          | ●              | ○                 |
| Technical Follow-up（システム外） | ●       | -                 |

System Administratorは上表の業務データを扱わず、ユーザー・マスタ・運用ルールの管理（BR-AD-001〜003）のみを担う。

`●`：主担当
`○`：参照・補助
`-`：対象外

# 8. 業務情報の流れ

「今何が起きているか」と「何が起き、何を観察し、何をしたか」を別の仕組みで扱う。

**(1) センサー → Alert（今何が起きているか）**

```text
IoT Sensors（3〜5分ごと）
        ↓
Sensor Database
        ↓
Alert rules / Thresholds
        ↓
Alert
        ├── Technical Manager：確認・対応・対応の記録・解決
        └── Farms Manager：閲覧（Dashboard / Farm Detail の Risk / Issue）
```

**(2) 運用業務 → Report（何が起き、何を観察し、何をしたか）**

```text
Pond Operations（Feeding / Mortality / Sampling / Health / Actuator）
  + Alert対応の記録
        ↓
Technical Manager（観察・Farm共通の項目・所見を入力）
        ↓
Daily / Weekly Report（センサー値は転記しない。Alert・センサーデータは参照のみ）
        ↓
Farms Manager（Review）
        ↓
必要に応じてFollow-up（システム外）
        ↓
Technical Manager
```

Sensors continuously observe. Alerts continuously detect. Technical Managers operate and respond. Reports document human operational activity. Farms Managers oversee Farm-level conditions and review operational reports.

# 9. 対象外

現時点では以下を業務要件の対象外とする。

- Buyer Matching
- Market Price Simulation
- Sales Strategy
- Buyer Contract Management
- Revenue Optimization
- International Sales Management
- Transportation / Export Management
- Farms ManagerによるRaw Sensor Monitoring
- Farms ManagerによるPondの技術的操作
- Farms ManagerによるActuator操作
- Farms ManagerによるPond Alertの確認・対応（Acknowledge / Resolve）
- Follow-up（Farms ManagerからTechnical Managerへの依頼）の依頼・回答・通知の機能（システム外で行う。BR-FM-006）
- Farm間の比較・順位付け（Farm Comparison）
- AI Recommendation / AI Insights / AIによるManagement Decision
- 収穫推奨日・利益予測・将来在庫（出荷量）予測
- 操作ログ（監査ログ）の閲覧画面
- System Administratorによる業務データ（水質・生産・Report）の閲覧・操作
- SSO・二段階認証（現行はメールアドレスとパスワードによるログイン）
