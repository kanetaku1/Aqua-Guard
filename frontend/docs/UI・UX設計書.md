## 2 UI/UX設計の目的と原則

### 2.1 設計の目的

本書は、Smart Shrimp Pond Management Systemの画面・操作・表示ルールを定義し、後続のフロントエンド設計で実装判断がぶれないようにするための基準文書である。

本システムのUIは、利用者が大量のデータを読むことではなく、異常や判断すべき事項を短時間で発見し、根拠を確認して適切な行動へ移れることを優先する。

### 2.2 基本原則

1. **結論を先に表示する**：画面上部に現在の状態、要対応事項、最新データ時点を表示する。
2. **役割に応じて情報量を分ける**：Farms Managerには経営判断に必要な集約情報、Technical Managerには現場対応に必要な詳細情報を表示する。
3. **予測と実績を分ける**：予測値、実績値、推定値をラベルと表示形式で明確に区別する。
4. **状態を色だけで伝えない**：色に加えてラベル、アイコン、形状、テキストを使用する。
5. **重大操作は人間が確認する**：AIはRecommendationを提示するが、意思決定とActuator操作の主体にはならない。
6. **最新性と欠損を隠さない**：データ取得時刻、更新遅延、通信断、センサー欠損を常に表示する。
7. **入力ミスを防ぎ、取り消し可能にする**：必須項目、単位、範囲、保存結果、監査記録を明確にする。

## 3 ブランド・ロゴ方針

### 3.1 ブランド定義

| 項目           | 定義                                                 |
| -------------- | ---------------------------------------------------- |
| 正式名称       | Smart Shrimp Pond Management System                  |
| 表示上の短縮名 | Smart Shrimp Pond                                    |
| ブランド人格   | 現場に寄り添う、信頼できる、判断が速い、データが明瞭 |
| 主な利用環境   | Farms ManagerのPC、Technical ManagerのPC・タブレット |
| ブランドカラー | 水域ブルー、マングローブグリーン                     |

ブランド表現は、装飾的・ゲーム的な雰囲気ではなく、養殖現場と経営判断の両方に適した落ち着いた業務システムとする。

### 3.2 ロゴ案

ロゴは、**エビのシルエット、水面のライン、センサーデータの波形**を抽象化したシンボルとワードマークの組み合わせとする。小さなサイズでも認識できるよう、細すぎる線や複雑なディテールは使用しない。

- シンボルのみ：アプリアイコン、favicon、狭いサイドバーで使用
- シンボル＋ワードマーク：ログイン画面、ヘッダー、エクスポート帳票で使用
- 単色版：印刷、背景色が複雑な場所、コントラスト確保が必要な場所で使用
- 禁止事項：縦横比の変更、過度な影・グラデーション、低コントラスト背景への配置、文字間隔の変更
- 安全領域：シンボル外周の高さの25%以上を空ける
- 素材形式：SVGを基本とし、favicon用にPNGまたはICOを用意する

ロゴ画像はブランド素材確定後に制作する。フロントエンドではロゴの差し替えでレイアウトが崩れないよう、表示領域を固定する。

## 4 デザイントークン

### 4.1 カラー

以下は初期候補であり、ブランド確認およびコントラスト検証後に最終確定する。ブランドカラーと状態を示す意味色は分離する。

| 用途         | 色名           | 候補値    | 使用ルール                                 |
| ------------ | -------------- | --------- | ------------------------------------------ |
| Primary      | Water Blue     | `#087EA4` | 主要ボタン、選択状態、リンク、進行中の表示 |
| Primary Dark | Deep Water     | `#075985` | ヘッダー、濃色ボタン、白文字の背景         |
| Secondary    | Mangrove Green | `#2F855A` | 補助ボタン、成長・供給・実績の補助表現     |
| Background   | Mist           | `#F4F8F7` | アプリケーション全体の背景                 |
| Surface      | White          | `#FFFFFF` | パネル、テーブル、フォームの背景           |
| Text         | Ink            | `#18323B` | 本文、主要数値、見出し                     |
| Muted Text   | Slate          | `#5B7078` | 補足、単位、更新時刻                       |
| Border       | Tide Line      | `#D6E3E5` | 境界線、区切り線                           |
| Normal       | Status Green   | `#237A57` | 正常、安定、完了                           |
| Attention    | Status Amber   | `#A15C00` | 注意、確認推奨                             |
| Warning      | Status Orange  | `#B54708` | 警告、対応が必要                           |
| Critical     | Status Red     | `#B42318` | 重大、即時対応が必要                       |
| Info         | Status Blue    | `#1769AA` | 情報、参考、システム通知                   |

- 状態色は必ず状態ラベルとアイコンを併記する。
- 本文と背景のコントラストはWCAG 2.2 AA相当を満たす。
- 赤と緑だけの比較を避け、形状、ラベル、パターン、位置でも区別する。
- Primary色を警告や正常の意味に流用しない。

### 4.2 文字・数値

- 日本語：`Noto Sans JP`、英語・インドネシア語：`Inter`または同等の可読性を持つWebフォントを候補とする。
- フォントサイズは固定トークンで管理し、画面幅に応じて文字を拡大縮小しない。
- 本文は16pxを基準、補助情報は14px以上、画面タイトルは24px以下を基準とする。
- 数値は桁区切りを使用し、単位を数値の直後または列見出しに表示する。
- センサー値には取得時刻を付ける。例：`DO 5.6 mg/L · 09:15 WIB`。
- 予測値には「予測」、実績値には「実績」、推定値には「推定」を明示する。

### 4.3 余白・形状

- 基本単位は8pxとし、主要な余白は8px、16px、24px、32pxで構成する。
- 業務パネルの角丸は4pxまたは8pxまでとする。
- 装飾目的の大きな角丸カード、浮遊する多重カード、過度な影は使用しない。
- クリック可能な要素は視覚的に操作可能であることが分かる状態を持つ。

### 4.4 共通ボタン設計

ボタンは「重要度」「危険度」「操作の確定性」に応じて、Normal / Secondary / Outline / Danger を基本とする。ラベルはテキスト主体にし、アイコンは補助的な表示に限定する。全パターンで高さ、間隔、フォーカス状態、無効状態のルールを統一し、役割ごとの差別は色とラベルで明確にする。

#### 4.4.1 サイズ

- ボタン本文の標準フォントサイズは14px / Semiboldを基準とする。
- 1行テキストの行高は20pxとし、最小タッチ領域44pxを満たすため、標準ボタン高さは44pxとする。
- 重要操作では48px、簡易操作では40pxとする。
- フォントサイズが増える場合は、行高と縦方向パディングを併せて増やし、最小高さ44pxを下回らないようにする。

| サイズ | 高さ | 文字サイズ | 横方向の余白 | 使い方                      |
| ------ | ---- | ---------- | ------------ | --------------------------- |
| SM     | 40px | 14px       | 16px〜20px   | 一覧内の軽い操作            |
| MD     | 44px | 14px       | 20px〜24px   | 標準操作、フォーム送信      |
| LG     | 48px | 16px       | 24px〜28px   | 主要CTA、画面上部の確定操作 |

- 最低タッチ領域は44pxを確保し、必要に応じてボタン全体の高さを拡張する。
- 1つの画面内では、同一意味のボタンは同一サイズに揃える。
- テキスト長が長い場合は、最小幅を確保したうえで改行せずにラベルを省略しない。

#### 4.4.2 バリエーションカラー（Variant）

| バリエーション | 背景      | 文字色    | 境界線    | 用途                               |
| -------------- | --------- | --------- | --------- | ---------------------------------- |
| Normal         | `#087EA4` | `#FFFFFF` | なし      | 主要アクション、保存、次へ         |
| Secondary      | `#2F855A` | `#FFFFFF` | なし      | 補助アクション、成長・計画・成功系 |
| Outline        | `#FFFFFF` | `#087EA4` | `#D6E3E5` | 取消、戻る、サブ操作               |
| Danger         | `#B42318` | `#FFFFFF` | なし      | 削除、リセット、危険な実行         |
| Ghost / Text   | 透明      | `#087EA4` | なし      | リンクに近い補助操作               |
| Disabled       | `#E7EEF0` | `#8AA0A6` | `#D6E3E5` | 利用不可                           |

- Normalは「確定・実行」を担い、Dangerは「破壊的・取り消し不能な操作」に限定する。
- Outlineは背景と同系統にしつつ、NormalまたはMuted Textへの明確な境界を持たせる。
- Secondaryは比較的軽い成功系アクションに使い、Normalとの併用時はNormalを優先表示する。
- Disabledは背景色を薄くし、テキストのコントラストと操作不可を明確にする。

#### 4.4.3 状態定義

| 状態     | Normal                  | Secondary  | Outline                 | Danger                  |
| -------- | ----------------------- | ---------- | ----------------------- | ----------------------- |
| Default  | 水色系ブルー            | 深緑系     | 白背景＋境界線          | 深い赤                  |
| Hover    | `#075985`               | `#1F6F4D`  | 影を軽く、文字色を濃く  | `#912018`               |
| Active   | さらに濃く              | さらに濃く | 背景を薄く              | `#7A1D16`               |
| Focus    | 2pxリング、色はNormal系 | 同上       | 2pxリング、色はNormal系 | 2pxリング、色はDanger系 |
| Disabled | `#E7EEF0` / `#8AA0A6`   | 同左       | 同左                    | 同左                    |

- フォーカスはキーボード利用時に必須とし、ボタンの輪郭線で視認性を確保する。
- 危険操作にはボタン色のみに頼らず、ラベル（例：削除する、リセット）と確認ダイアログを併用する。
- 実装上の状態名はHover / Active / Focus / Disabledを用い、Defaultは通常状態とする。

#### 4.4.4 OutlineとDangerの設計ルール

- Outlineは通常操作を抑えつつ、必要なときに「戻る」「キャンセル」「比較」「詳細」を表現する。
- Dangerは「破壊・削除・解除・上書き」のみで使用し、通常の保存や確認画面では使わない。
- Dangerを使うボタンは、同じ画面内で他のアクションと視覚的に区別できるよう、同列にNormalかOutlineを置く。
- 必要に応じてDangerボタンの前に警告アイコンを置き、確認ダイアログを必須にする。

#### 4.4.5 ボタンの使用パターン

- 基本ボタンはテキストのみで構成し、操作の意図をラベルで明確にする。
- 同一行に複数のボタンを置く場合、重要度が高いものは右側に配置し、危険操作は右端または最後に配置する。
- 重要操作ではNormalを優先し、補助操作はOutlineまたはSecondaryで表現する。
- 以下のような用途に応じて、動詞に応じたラベルを使用する。
  - 保存、登録、送信
  - 追加、参照、比較
  - キャンセル、戻る
  - 削除、リセット、上書き

#### 4.4.6 候補のボタン組み合わせ

| 操作性       | 典型的な例             | 推奨バリエーション  |
| ------------ | ---------------------- | ------------------- |
| 重要な確定   | 保存、登録、送信       | Normal              |
| 補助的な実行 | 追加、参照、比較       | Secondary / Outline |
| 取消・戻る   | キャンセル、閉じる     | Outline             |
| 危険な実行   | 削除、リセット、上書き | Danger              |
| 低優先操作   | 一時保存、詳細         | Ghost / Text        |

### 5 共通レイアウト

### 5.1 アプリケーションシェル

```text
┌──────────────────────────────────────────────────────────────┐
│ ロゴ │ Farm / Estate切替 │ 最新更新時刻 │ 通知 │ 言語 │ User │
├──────────────┬───────────────────────────────────────────────┤
```

- ページ上部は「結論または最重要状態」→「フィルター」→「詳細」の順にする。
- ファームと池の切替状態は画面遷移後も保持し、誤操作を防ぐ。

| 表示幅       | 対象                          | 方針                                         |

## 6 役割別の情報設計

### 6.1 Farms Manager

全社の判断を短時間で行えるよう、情報の優先順位を以下とする。

1. 結論：全体状態と最優先の要対応事項
2. 状態サマリー：総池数、正常・注意・警告の内訳、最新更新時刻
3. 3領域分析：収益最適化、生物学的リスク、将来在庫
4. アラート：重要度、Farm、Pond、発生時刻、推奨確認項目
5. 根拠：集約KPI、分析に使用した期間、主要因、推奨アクション

Farms Managerには生のセンサー値を表示しない。S-06のドリルダウンで表示できるのは、集約KPI、スコア、トレンドの要約、分析根拠、推奨アクション、データ更新時刻までとする。

### 6.2 Technical Manager

現場対応を短時間で行えるよう、情報の優先順位を以下とする。

1. 現在の異常：未確認・重大なアラート、通信断、センサー欠損
2. 池一覧：池ごとの状態、最新値、更新時刻、選択状態
3. 選択池の詳細：DO、pH、水温、濁度、TDS、水位の時系列
4. 対応支援：AI Recommendation、閾値、推奨アクション
5. 業務操作：日次報告、週次サンプリング、自動制御の監視・承認・Override

Technical Managerには担当Farm内のIoT詳細値、日次・週次データ、アラートの詳細を表示する。

## 8 状態表示とデータ品質

### 8.1 画面共通状態

| 状態           | 表示内容                                                         |
| -------------- | ---------------------------------------------------------------- |
| Loading        | 対象領域にローディング表示を出し、前回値を新しい値と誤認させない |
| Empty          | データが存在しない理由と、可能な次の操作を表示                   |
| Error          | 取得失敗の概要、再試行、発生時刻、問い合わせ先を表示             |
| Offline        | 通信断、最後に取得できた時刻、操作制限を表示                     |
| Stale          | 許容時間を超えたデータに「更新遅延」を付け、現在値と区別する     |
| Sensor Missing | 対象センサー、欠損期間、代替できる情報、対応先を表示             |
| Forbidden      | 権限不足の理由と、参照可能な範囲を表示。値を推測させない         |

### 8.2 アラート状態

アラートは以下の状態を持ち、状態変更者と変更時刻を記録する。

1. 未確認：発生したが担当者が確認していない
2. 確認済み：担当者が内容を確認した
3. 対応中：現場対応または監視を開始した
4. 解決済み：条件が解消され、対応が完了した

詳細画面には、何が起きているか、現在値、基準値、トレンド、発生時刻、推奨アクション、確認者、対応履歴を表示する。

## 9 AI Recommendationと自動制御のUI

### 9.1 AI Recommendation

AI Recommendationは、以下の情報を一つのまとまりとして表示する。

- 推薦内容
- 対象の池と予測期間
- 主要な根拠データと対象期間
- 信頼度または確度（モデルが提供する場合）
- 推薦／予測／実績の区別
- 推薦を採用、却下、保留した記録
- 「最終判断はTechnical Managerが行う」という責任表示

AIはActuatorを直接操作しない。推薦から制御操作へ進む場合も、Technical Managerの確認とSafety Layerの許可を必須とする。

### 9.2 自動制御

S-14では、機器ごとに以下を表示する。

- Actuatorの名称、現在状態、制御モード、自動／手動
- Safety Layerによる許可状態
- 直近の制御理由、実行時刻、実行結果
- 承認、Override、緊急停止の操作状態
- 操作を実行したユーザー、実行時刻、監査ログ

重大操作には確認ダイアログを表示し、対象機器、想定される影響、解除条件を明示する。Safety Layerの許可範囲外の操作は無効化し、無効理由を表示する。

## 11 多言語・日時・単位

- Technical Managerの主要画面はインドネシア語を必須とする。
- Farms Managerはインドネシア語を基本とし、英語を切り替え可能にする。翻訳未登録の文言は識別可能な状態で表示し、意味不明な空欄にはしない。
- 言語切替はユーザー単位で保持し、ログイン後の全画面に適用する。
- 日時は原則としてインドネシア西部時間（WIB、UTC+7）で表示し、画面上にタイムゾーンを示す。
- 日付は`DD MMM YYYY`、時刻は`HH:mm`を基本とする。APIやエクスポートの形式はフロントエンド設計で別途定義する。
- 水質の単位はデータ定義に従い、DOは`mg/L`、水温は`°C`、濁度は`NTU`、水位は`cm`を基本とする。

## 12 アクセシビリティ

- 色だけに依存せず、テキスト、アイコン、形状で状態を表現する。
- キーボードのみで主要操作を完了できるよう、フォーカス順とフォーカス表示を定義する。
- 入力項目には可読なラベルを付け、エラーは項目単位で関連付ける。
- グラフには凡例と表形式の代替情報を提供する。
- 主要なタッチ操作領域は44px以上とする。
- 動きのある表示は情報理解に必要な範囲に限定し、ユーザー設定で抑制できる設計を検討する。
