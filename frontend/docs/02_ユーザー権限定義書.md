# ユーザー権限定義書

**Role-Based Access Control / RBAC**

---

## 1. 目的

Smart Shrimp Pond Management Systemにおける、ユーザーRole、管理対象、情報アクセス範囲、基本操作権限を定義する。

本書では、業務フロー、画面構成、UI/UX、KPI・データ項目、システム内部の実装は定義しない（01_業務要件書・04_KPI・データ項目定義書・05_画面・機能要件書を参照）。

---

## 2. 管理階層とRole

```text
Company
  ├── Farm A
  │     ├── Pond 01
  │     └── Pond 02
  ├── Farm B
  │     ├── Pond 01
  │     └── Pond 02
  └── Farm C
        ├── Pond 01
        └── Pond 02

Farms Manager     → Companyが管理する複数Farm
Technical Manager → 担当Farm内のPond
```

| Role                  | 管理単位 | 主な役割                                               | 姿勢 |
| --------------------- | -------- | ------------------------------------------------------ | --- |
| **Farms Manager**     | Farm     | 複数Farmの状態・生産状況を把握し、Farm単位の判断を行う | VIEW / UNDERSTAND |
| **Technical Manager** | Pond     | 担当Farm内のPondを管理し、技術・運用上の判断を行う     | MONITOR / INVESTIGATE / MANAGE |

Farms ManagerはPondの現場運用を直接管理しない。Technical Managerは担当Farmの範囲を超えて管理しない。

---

## 3. 権限の種類

| Permission      | 意味                                 |
| --------------- | ------------------------------------ |
| **View**        | 情報を閲覧する                       |
| **Create**      | 情報を新規登録する                   |
| **Manage**      | 担当範囲の情報を登録・更新・管理する |
| **Acknowledge** | Alertを確認し、対応状態を更新する    |
| **Decide**      | 担当範囲における業務上の判断を行う   |
| **Execute**     | 許可された操作を実行する             |
| **Submit**      | 作成した報告を提出する               |

---

## 4. Role × Permission

| 対象                                   | Farms Manager | Technical Manager           |
| -------------------------------------- | ------------- | --------------------------- |
| Company情報                            | View          | -                           |
| Farm情報                               | View / Decide | View                        |
| Farm Status（環境・生産・運用）        | View / Decide | View                        |
| Farm-level Risk / Issue                | View / Decide | View                        |
| Pond Status                            | View\*        | View / Decide               |
| Pond-level IoT情報（センサー値・時系列） | -\*\*         | View / Decide               |
| Pond Alert                             | View\*        | View / Acknowledge / Decide |
| Farm Production Status                 | View / Decide | View                        |
| Pond Production Summary（Pond別の生産KPI） | View      | View / Manage               |
| Feeding / Mortality / Sampling Records | -\*\*\*       | Create / Manage             |
| Daily / Weekly Report                  | View          | Create / Submit / View      |
| Actuator操作                           | -             | Execute                     |

- `*` Farms Managerが参照できるPondの状態・Alertは、Farmの状態把握に必要な集約情報（異常の有無、種類、重大度、傾向、継続時間、対象Pond、対応状態）に限る。
- `**` 生のセンサー値・センサー時系列は参照しない。環境の状態は集約した傾向（例：Pond 02 · DO · ↓ Decreasing · Warning · 2 days）として参照する。
- `***` 個々の記録は参照しない。記録から算出した生産KPIは Pond Production Summary として、記録の要約は Daily / Weekly Report として参照する。

## 5. 情報アクセス範囲

### 5.1 Farms Manager

#### アクセス可能

- Companyが管理する全Farmの情報
- Farm-levelの環境状態、生産状況、Risk / Issue
- Farmの状態把握に必要なPond-levelの集約情報（異常・傾向・対応状態）
- Pond Production Summary（Pond別のDOC、ABWと目標比、ADG、Survival Rate、FCR、Biomass）
- Daily / Weekly Report（提出済みのもの）

#### アクセスしない

- 生のセンサー値、センサー時系列データ
- Feeding / Mortality / Sampling の個々の記録
- Pond Alertの確認・対応操作
- PondのActuator操作および直接的な運用操作
- 下書き（Draft）状態のReport

### 5.2 Technical Manager

#### アクセス可能

- 担当Farmの情報
- 担当Farm内のPond情報
- Pondの詳細なIoT・水質情報（現在値・時系列・履歴）
- Pond Alert（確認・対応状態の更新）
- Feeding / Mortality / Sampling Records（登録・更新）
- Daily / Weekly Report（作成・下書き保存・提出・履歴）
- Safety Layer等で許可されたActuator操作

Technical Managerは、担当Pondの監視、Alertの確認、技術・運用上の判断を行う。

---

## 6. 権限設計原則

1. 最小権限を原則とする。
2. Roleごとに必要な情報と操作のみを提供する。
3. Farms ManagerはFarm単位、Technical ManagerはPond単位で管理する。
4. 情報の閲覧と操作の権限を分離する。閲覧のみのRoleには操作部品を表示しない。
5. Farms Managerが参照するPondの環境情報は、Farmの状態把握に必要な集約情報に限定する。生産KPIは記録から算出した値であり、生のデータではないためPond単位で参照できる。
6. Actuator操作はTechnical Managerの許可範囲に限定し、Safety Layerの制約に従う。
7. 本書で定義しない業務ルールや詳細仕様は、01_業務要件書・04_KPI・データ項目定義書・05_画面・機能要件書で定義する。
