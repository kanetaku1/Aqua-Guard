# ユーザー権限定義書

**Role-Based Access Control / RBAC**

---

## 1. 目的

AquaGuardにおける、ユーザーRole、管理対象、情報アクセス範囲、基本操作権限を定義する。

本書では、業務フロー、画面構成、UI/UX、KPI・データ項目、システム内部の実装は定義しない（01_業務要件書・04_KPI・データ項目定義書・05_画面・機能要件書を参照）。

---

## 2. 管理階層とRole

```text
Company
  ├── Farm A
  │     ├── Pond 01
  │     └── Pond 02
  ├── Farm B
  │     ├── Pond 01
  │     └── Pond 02
  └── Farm C
        ├── Pond 01
        └── Pond 02

Farms Manager        → Companyが管理する複数Farm
Technical Manager    → 担当Farm内のPond
System Administrator → システムの設定（ユーザー・マスタ・運用ルール）
```

| Role                  | 管理単位 | 主な役割                                               | 姿勢 |
| --------------------- | -------- | ------------------------------------------------------ | --- |
| **Farms Manager**     | Farm     | 複数Farmの状態・生産状況を把握し、Farm単位の判断を行う | VIEW / UNDERSTAND |
| **Technical Manager** | Pond     | 担当Farm内のPondを管理し、技術・運用上の判断を行う     | MONITOR / INVESTIGATE / MANAGE |
| **System Administrator** | システム | ユーザー・Farm/Pond/機器のマスタ・運用ルールを管理する | CONFIGURE / ADMINISTER |

Farms ManagerはPondの現場運用を直接管理しない。Technical Managerは担当Farmの範囲を超えて管理しない。System Administratorは養殖の業務データを閲覧・操作しない。

1人のユーザーに割り当てるRoleは1つとする。

---

## 3. 権限の種類

| Permission      | 意味                                 |
| --------------- | ------------------------------------ |
| **View**        | 情報を閲覧する                       |
| **Create**      | 情報を新規登録する                   |
| **Manage**      | 担当範囲の情報を登録・更新・管理する |
| **Acknowledge** | Alertを確認し、対応状態を更新する（対応の記録 Record action・解決 Resolve を含む） |
| **Decide**      | 担当範囲における業務上の判断を行う   |
| **Execute**     | 許可された操作を実行する             |
| **Submit**      | 作成した報告を提出する               |
| **Administer**  | ユーザー・マスタ・運用ルールを登録・変更・無効化する |

## 4. Role × Permission

| 対象                                   | Farms Manager | Technical Manager           |
| -------------------------------------- | ------------- | --------------------------- |
| Company情報                            | View          | -                           |
| Farm情報                               | View / Decide | View                        |
| Farm Status（環境・生産・運用）        | View / Decide | View                        |
| Farm-level Risk / Issue                | View / Decide | View                        |
| Pond Status                            | View\*        | View / Decide               |
| Pond-level IoT情報（センサー値・時系列） | -\*\*         | View / Decide               |
| Pond Alert                             | View\*（閲覧のみ） | View / Acknowledge（Record action・Resolve）/ Decide |
| Farm Production Status                 | View / Decide | View                        |
| Pond Production Summary（Pond別の生産KPI） | View      | View / Manage               |
| Feeding / Mortality / Sampling Records | -\*\*\*       | Create / Manage             |
| Daily / Weekly Report                  | View          | Create / Submit / View      |
| Actuator操作                           | -             | Execute                     |

System Administrator は上表の業務データにアクセスしない（すべて `-`）。管理機能の権限は次のとおり。

| 対象 | System Administrator | Farms Manager | Technical Manager |
| --- | --- | --- | --- |
| ユーザー（招待・Role・担当Farm・無効化・パスワード再設定メール） | Administer | - | - |
| Farm・Pondのマスタ | Administer | -（業務画面で閲覧） | -（業務画面で閲覧） |
| センサー・Actuatorの割り当て | Administer | - | -（Pond Detailで状態を閲覧・Actuatorを操作） |
| 水質の閾値・目標成長曲線・運用ルール | Administer | -（判定結果を閲覧） | -（判定結果を閲覧） |
| 自分のパスワード・表示言語 | Manage | Manage | Manage |

- `*` Farms Managerが参照できるPondの状態・Alertは、Farmの状態把握に必要な集約情報（異常の有無、種類、重大度、傾向、継続時間、対象Pond、対応状態、TMが実施した対応、継続中 / 解決済み）に限る。AlertはSensor Databaseから直接発報され、Reportの提出を前提としない。
- `**` 生のセンサー値・センサー時系列は参照しない。環境の状態は集約した傾向（例：Pond 02 · DO · ↓ Decreasing · Warning · 2 days）として参照する。
- `***` 個々の記録は参照しない。記録から算出した生産KPIは Pond Production Summary として、記録の要約は Daily / Weekly Report として参照する。

## 5. 情報アクセス範囲

### 5.1 Farms Manager

#### アクセス可能

- Companyが管理する全Farmの情報
- Farm-levelの環境状態、生産状況、Risk / Issue
- Farmの状態把握に必要なPond-levelの集約情報（異常・傾向・対応状態）
- Pond Production Summary（Pond別のDOC、ABWと目標比、ADG、Survival Rate、FCR、Biomass）
- Daily / Weekly Report（提出済みのもの）

#### アクセスしない

- 生のセンサー値、センサー時系列データ
- Feeding / Mortality / Sampling の個々の記録
- Pond Alertの確認・対応操作
- PondのActuator操作および直接的な運用操作
- 下書き（Draft）状態のReport

### 5.2 Technical Manager

#### アクセス可能

- 担当Farmの情報
- 担当Farm内のPond情報
- Pondの詳細なIoT・水質情報（現在値・時系列・履歴）
- Pond Alert（確認・対応の記録・解決）
- Feeding / Mortality / Sampling Records（登録・更新）
- Daily / Weekly Report（作成・下書き保存・提出・履歴）。センサー値はReportに入力しない（Alert・センサーデータは参照のみ）
- Safety Layer等で許可されたActuator操作

Technical Managerは、担当Pondの監視、Alertの確認、技術・運用上の判断を行う。

### 5.3 System Administrator

#### アクセス可能

- ユーザー一覧、Role、担当Farm、アカウントの状態、最終ログイン日時
- Farm・Pondのマスタ（名称、所在地、面積、稼働状態）
- センサー・Actuatorの割り当てと接続状態（機器の稼働確認のため）
- 水質の閾値、目標成長曲線、運用ルール

#### アクセスしない

- センサー値・時系列、Pond Alert、生産KPI、Daily / Weekly Report などの業務データ
- Actuatorの操作

---

## 6. 権限設計原則

1. 最小権限を原則とする。
2. Roleごとに必要な情報と操作のみを提供する。
3. Farms ManagerはFarm単位、Technical ManagerはPond単位で管理する。
4. 情報の閲覧と操作の権限を分離する。閲覧のみのRoleには操作部品を表示しない。
5. Farms Managerが参照するPondの環境情報は、Farmの状態把握に必要な集約情報に限定する。生産KPIは記録から算出した値であり、生のデータではないためPond単位で参照できる。
6. Actuator操作はTechnical Managerの許可範囲に限定し、Safety Layerの制約に従う。
7. 管理（Administer）と業務（View / Manage / Execute）の権限を分離する。System Administratorは業務データを扱わず、FM・TMは管理機能を持たない。
8. 本書で定義しない業務ルールや詳細仕様は、01_業務要件書・04_KPI・データ項目定義書・05_画面・機能要件書で定義する。

## 7. 認証とアカウント

| 項目 | 定義 |
| --- | --- |
| ログイン方式 | メールアドレス＋パスワード |
| アカウントの作成 | System Administratorが招待する。招待メールのリンクから本人がパスワードを設定して有効化する（リンクの有効期限72時間） |
| アカウントの状態 | Invited（招待済み・未設定）→ Active（利用中）→ Deactivated（無効化）。削除はしない |
| パスワード | 10文字以上、英字と数字を含む。再設定はメールのリンクから行う（有効期限1時間） |
| ログインの失敗 | 5回連続で失敗したら15分間ロックする |
| セッション | 操作がない状態が12時間続いたらログアウトする |
| ログイン後の画面 | Farms Manager → FM Dashboard、Technical Manager → TM Dashboard、System Administrator → Users |
| 最後のSystem Administrator | 最後の1人は無効化・Role変更できない。自分自身も無効化できない |
