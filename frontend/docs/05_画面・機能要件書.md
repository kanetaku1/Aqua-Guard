# 画面・機能要件書

## Screen & Functional Requirements

## 1. 目的

本書は、01_業務要件書および02_ユーザー権限定義書に基づき、AquaGuardに必要な**画面、画面遷移、画面ごとの表示内容（優先順）、主要機能**を定義する。

- 各画面の詳細な構造（セクション → 部品 → 状態違い）は「06_画面構成ツリー」
- KPIの算出・集計・閾値は「04_KPI・データ項目定義書」
- 色・サイズ・部品の使い方は「07_UI・UX設計書」「08_デザインシステム定義書」

### 2.3 画面遷移

```text
FM:  Dashboard ─→ Farm Detail ─→ Latest report ─→ Report Detail
        └─→ Farm List ─→ Farm Detail
     Reports ─→ Report List ─→ Report Detail

TM:  Dashboard ─→ Pond Detail（Pond card / Active Alert から）
        └─→ Pond List ─→ Pond Detail（タブ）
     Reports ─→ Daily / Weekly Report（Create · Edit · Submit · History）

SA:  Users（Drawerで詳細・招待）
     Farms & Ponds ─→ Farm List ─→ Farm Detail（Farm Info / Ponds / Devices）
     Settings（Thresholds / Growth Targets / Rules）

認証: Login ─→ Roleごとの最初の画面（FM Dashboard / TM Dashboard / Users）
      Login ─→ Forgot Password ─→（メール）─→ Set Password ─→ Login
      招待メール ─→ Set Password（招待）─→ Roleごとの最初の画面
```

- 新しい画面は、必要な情報の粒度または業務タスクが変わるときだけ作る。同じ対象の観点の切り替えはタブで行う（Pond Detail、Report種別）。
- Farm Detail の Pond の異常は、TMが Pond Detail で調査する対象である（役割をまたぐ関係）。FMの画面からTMの画面へのリンクは置かない。
- タブ・絞り込みの状態はURLに保持する。

## 3. 共通機能

| ID | 機能 | 内容 |
| --- | --- | --- |
| SCR-COM-001 | Authentication | メールアドレスとパスワードで認証し、Roleに応じた最初の画面を表示する（AU-01〜03） |
| SCR-COM-002 | Role-Based Access Control | Roleに応じてアクセスできる情報と操作を制御する。操作権限のない部品は表示しない |
| SCR-COM-003 | Data Scope Control | FM：Company配下の全Farm／TM：担当FarmとそのPond |
| SCR-COM-004 | Status Display | Farm・Pond・Report・Alertの状態を共通の表示体系で示す |
| SCR-COM-005 | Data Freshness | ヘッダーにデータの鮮度（Live / Delayed）と同期時刻（WIB）を表示する |
| SCR-COM-006 | Language | 言語を切り替える（TMはインドネシア語必須、FMはインドネシア語／英語） |
| SCR-COM-007 | Date Input | 日付の入力はすべてカレンダーから選ぶ（表示形式 `DD MMM YYYY`）。記録の日付は未来日を選べない（サンプリング予定日などは選べる） |

共通レイアウト：Global Header（ブランド・対象範囲・データ鮮度・言語・ユーザー）＋ Role別サイドバー ＋ Page Header ＋ 本文。System Administratorのヘッダーはデータ鮮度を表示しない（業務データを扱わないため）。認証画面は中央のカードだけのレイアウト。

## 4. Farms Manager

### FM-01 Dashboard

> **Companyが管理するFarmの状態を把握し、どのFarmを見るべきか判断する。**

| 優先 | セクション | 内容 |
| --- | --- | --- |
| 1 | Farm Status | 状態別のFarm数。Farm一覧表（Farm〔Pond数〕、Status、**Main reason**〔状態の根拠を1文で〕、Water quality〔範囲外のPond数〕、Growth〔目標より遅れているPond数〕、Operations〔設備・センサー・Report〕→ Farm Detail）。Status は3観点のうち最も重いもの（Overall という別の状態は持たない） |
| 2 | Risk / Issue | 全Farmの未解決のIssue。**Alertから直接（ライブ）表示**し、Reportの提出を待たない。環境の傾向（Parameter・Trend・継続時間）、重大度、対応状態を含む（閲覧のみ） |
| 3 | Production Status | 総Biomass（推定・合計）、Survival Rate（推定・重み付き＝Σ推定生存尾数 ÷ Σ放養尾数。単純平均と誤読されないよう「Avg.」は付けず、補足に Weighted by stocked PL と書く）、成長目標より遅れているPond数（全体。画面表記 Ponds behind target。Farm Detail・Weekly の Growth vs Target は「On track の数」なので、同じ名前で逆の数を出さない）の3枚のKPI。Farm別の遅れは Farm Status 表の Growth 列で示す（Farmが増えても表が崩れないように、Farm別の表は置かない）。平均ABW等の平均値は表示しない |

- 環境の傾向は Risk / Issue に統合した（同じ内容を2か所に出さない）。
- Farm Status 表は「どのFarmが・なぜ」を事実（Pond数）で示し、Risk / Issue は個々の問題（Pond・傾向・継続時間・対応状態）を示す。同じ問題でも粒度を変えて見せる（07 §3 G1）。
- Recent Reports は置かない。Reportは Reports 画面と Farm Detail ヘッダーの Latest report リンクから開く。Reportの未提出は Farm の Operational Status に反映する（Risk / Issue には影響しない）。

| ID | 機能 | 内容 |
| --- | --- | --- |
| FM-D-001 | Farm Status Summary | 各Farmの状態を一覧表示 |
| FM-D-002 | Risk / Issue Summary | 確認が必要な問題を表示 |
| FM-D-003 | Production Status Summary | 会社全体で意味を持つ生産の値を表示 |
| FM-D-004 | Pond Anomaly Summary | Pondの重要な異常・傾向を Risk / Issue の中で表示（統合） |
| FM-D-005 | ~~Recent Reports~~ | 廃止（Reportは Reports 画面と Farm Detail の Latest report リンクから開く） |
| FM-D-006 | Farm Navigation | 選択したFarmのFarm Detailへ移動 |

### TM-04 Daily Report / TM-05 Weekly Report

> **担当FarmのDaily / Weekly Reportを作成・提出する。**

- タブ：Create / Edit と History。
- 入力のセクションは FM-05 / FM-06 と同じ順番・同じ名前にする（TMが提出した内容＝FMが読む内容）。
- **Reportはその日・その週の運用業務を記録するもので、センサー値を手入力・転記しない。** 水質の履歴は Pond Detail › IoT / Water Quality にあり、Reportからはリンクで参照する。ReportはAlertの前提ではない（Alertはセンサーから直接発報される）。
- **確認が中心の画面にする。** 給餌・死亡（Pond Detail の記録）・設備（Actuator）・その日のAlert（Alertシステム）・Alert対応の記録・生産KPI（サンプリング）は自動で集め、読み取り専用で表示する。Ponds画面での日々の入力とAlert対応の記録で Report の約8割が完成する。
- Daily のセクション（FM-05 と同じ順番）：1 Report Information · 2 Feeding · 3 Mortality · 4 Health Condition · 5 Environment / Weather · 6 Equipment Status · 7 Major Alerts / Issues · 8 Actions Taken · 9 Technical Manager Summary*。
- 上部に**完成度のチェックリスト**を表示する：Feeding · Mortality（記録から）、Equipment（自動）、Health（任意）、Farm input（Weather*、Summary*）。水質の項目は持たない。
- Daily の Feeding / Mortality / Health は Pond 別の**1つの表**（給餌・摂餌・死亡・エアレーター・健康状態）にまとめ、行の **Edit** で Pond ごとの Drawer（`?pond=1`：摂餌・トレイの状態、健康状態＋観察項目〔Reduced appetite / Abnormal swimming / Gill discoloration / Shell condition / Other visible abnormality〕＋メモ。給餌・死亡は記録から読み取り専用）を開く。記録そのものの修正は Pond Detail で行う。
- Major Alerts / Issues はその日のAlertを自動で参照する（Pond、Alert、Occurred、Duration、Status、リンク **View Alert** / **View Water Quality Data**）。TMは項目を除外できるが、値を入力し直さない。
- Actions Taken（Time、Pond、Action、Result / Outcome）は、Alert対応の記録（参照元「Alert handling」）と Actuator の操作（参照元「Actuator log」）から自動で入り、**Add action** で手入力を追加できる。
- Farm共通の入力（天候・降雨・環境上の出来事・発電機）と Actions Taken、Alerts / Issues と Summary をそれぞれ横に並べて縦の長さを抑える。
- Weekly は FM-06 と同じ構成（Production Status、Feeding / Mortality Summary のドーナツ、Ponds this week のタブ `?pw=growth / wq / feed / lab`）。Water quality trends は Sensor Database から自動集計し、TMは任意のコメントだけを加える。Major Alerts / Issues は週のAlertから自動集計し、TMは Cause / Action / Outcome を追記できる。
- Technical Managerが入力するのは、摂餌・トレイの状態、健康状態の観察（注意があるPondだけ。他はNormalのまま）、Farm共通の項目（天候・降雨・環境上の出来事・発電機）、手入力の対応、所見（Summary）。Weekly では Laboratory の確認、Water quality trends のコメント、Major Alerts / Issues の追記、Weekly Technical Summary。
- Weekly Report には週次サンプリングの測定状況（測定済みのPond数・未測定のPond）を表示する。
- 記録から参照した値は初期入力し「From records」等の参照元を表示する。値の修正は元の記録（Pond Detail）で行う。
- 画面下に操作バー（状態・保存時刻、Save Draft、Submit）を固定表示する。Submit は確認ダイアログを通す。
- 状態：Draft → Submitted。提出済みは閲覧のみ。

### AD-04 Settings

> **判定に使う運用ルールを設定する。** 値の意味は「04_KPI・データ項目定義書」。

| タブ | 内容 | ID |
| --- | --- | --- |
| Thresholds | 対象（Default for all Farms / Farmごとの上書き）、**境界値エディタ**：項目ごとに1行、左に Low side（Critical・Warning・Attention が始まる値 “below”）、中央に Normal（自動計算・入力しない）、右に High side（Attention・Warning・Critical “above”）。1つの欄には数値1つだけ。使わない側は “Not used”。行の下に範囲のプレビュー（色帯と境界値）。順序の誤り（例：Warning が Attention より Normal 側）は欄のエラーで示す。水質（センサー）と Laboratory の2枚。未保存の変更数とエラー数を操作バーに表示、Save changes（Primary → 確認ダイアログ） | AD-S-001 Thresholds |
| Growth Targets | DOCごとの目標ABWの表（編集可）、On trackの幅（±%）、目標曲線のプレビュー、Save changes | AD-S-002 Growth Targets |
| Rules | Reportの提出期限（Daily・Weekly）、データ鮮度（Delayed・Offlineとみなす時間）、Attentionが続いたらAlertにする時間、Farm Production Statusの境界値、Save changes | AD-S-003 Operational Rules |

- 保存は確認ダイアログを通し、「保存以降の判定に適用され、過去のAlert・Reportは変わらない」ことを示す。
- 入力が範囲として矛盾する場合（例：Warningの下限がAttentionより上）はその欄にエラーを表示し、保存できない。
- Thresholds：境界を持てる側は項目ごとに決まっている（DO は Low のみ、TAN・NO2・Vibrio は High のみ）。持てない側は “Not used” の表示だけで入力欄を出さない。持てる側の欄は空にすると “Not used”。
- Thresholds の Farm ごとの上書き：上書きしていない項目は「Uses the default」と表示し、値を変えるとその項目が上書きになる。上書き中の項目は「Use the default」で初期値に戻せる。Apply to の選択肢に上書きの件数を出す（例「Farm D (1 override)」）。初期値の保存の確認では、初期値を使う Farm と、上書きを持つ Farm（例「Farm D keeps its DO override」）を示す。
- Growth Targets：曲線の点は2点以上。DOC は上の行より後、目標 ABW は前の点より大きい。On-track の幅は 1〜50%。
- Rules：Weekly Report の締切は翌週の曜日と時刻（初期値 月曜 12:00）。Offline は Delayed より長く、Production の Warning は Attention より大きい。
