# 用語定義

本書は、業務・画面で使う用語を定義する。KPIの計算式・閾値・判定ルールは「04_KPI・データ項目定義書」で定義する。

## 1. 組織・Role

| 用語 | 定義 |
| --- | --- |
| Company | 複数のFarmを管理する養殖会社 |
| Farm | 複数のPondから構成される養殖管理単位 |
| Pond | エビ養殖を行う現場単位（池） |
| Farms Manager | Company配下の全Farmの状態・生産状況を把握するRole（VIEW / UNDERSTAND） |
| Technical Manager | 担当Farm内のPondを監視・管理するRole（MONITOR / INVESTIGATE / MANAGE） |
| System Administrator | ユーザー・Farm/Pond/機器のマスタ・運用ルールを管理するRole（CONFIGURE / ADMINISTER）。業務データは扱わない |
| 担当Farm | Technical Managerに割り当てられた1つのFarm。TMはこのFarmとそのPondだけを扱う |
| マスタ | Farm・Pond・機器（センサー・Actuator）の登録情報。養殖の記録（放養・給餌等）とは区別する |
| 運用ルール | 水質の閾値、目標成長曲線、Reportの提出期限など、判定に使う設定値。System Administratorが設定する |

## 2. 情報の種類（区別して扱う概念）

| 用語 | 定義 | 例 |
| --- | --- | --- |
| Farm Status | Farm全体の状態。Water quality（Environmental）・Growth（Production）・Operations（Operational）の3観点のうち最も重いもの。画面では根拠（Main reason と各観点の該当Pond数）を併せて示す | Farm A · Warning（Water quality: 3 of 8 Ponds out of range） |
| Environmental / Pond Trend | Pondで起きている環境の異常・傾向。Farms Managerには生の値ではなく集約した傾向として示す | Pond 02 · DO · ↓ Decreasing · Warning · 2 days |
| Production Status | エビの生産状況。Pond単位で算出し、Farm単位では集計可能な値のみ示す | Biomass、Survival Rate、FCR、Growth vs target |
| Pond Production Summary | Pondごとの生産KPIの一覧（DOC、ABWと目標比、ADG、SR、FCR、Biomass） | Pond 02 · DOC 62 · 13.8 g（−8% Behind） |
| Risk / Issue | Farm全体として把握すべき問題・異常。単一のPond Alertではなく、継続・複数Pond・生産への影響を持つもの。環境上の問題はAlertから直接（Reportを介さず）表示する。AIによる予測ではない | Water Quality · Pond 02 · Warning · 2 days · Ongoing |
| Sensor Data | IoTセンサーが3〜5分ごとに計測し、Reportとは独立してSensor Databaseに保存する水質データ（DO・pH・水温・TDS・濁度・水位）。時系列はTechnical ManagerがPond Detailで確認する | Pond 02 · DO 4.1 mg/L · 09:05 |
| Pond Alert（Alert） | Sensor Databaseのデータを閾値（Alert rule）で判定し、自動で発報される通知。Reportの作成・提出を前提としない。Technical Managerが確認・対応・対応の記録・解決を行い、Farms Managerは閲覧する | DO below threshold（4.1 < 4.5） |
| Action record（対応の記録） | Technical ManagerがAlert対応として記録する内容（時刻・対応種別・メモ）。その日のDaily Reportの Actions Taken に自動で反映する | 09:20 · Increased aeration · Pond 02 |
| Daily Report | Technical Managerが1日ごとに作成・提出する、「その日に運用上何が起き、TMが何を観察し、何をしたか」の構造化報告（給餌・死亡・健康状態・天候・設備・その日のAlertと対応・所見）。センサー値は手入力・転記せず、Alert・センサーデータは参照のみ | Daily Report · Farm A · 28 Sep 2026 |
| Weekly Report | Technical Managerが週ごとに作成・提出する、「その週にFarmがどう進んだか」の報告（生産状況・水質の傾向・検査結果・主要な問題と対応）。水質の傾向はSensor Databaseから自動集計する。Daily Reportの7日分ではない | Weekly Report · Farm A · 22–28 Sep 2026 |

## 3. 水質・設備

| 用語 | 定義 |
| --- | --- |
| DO | 溶存酸素。エビの生存に直結する水質指標 |
| pH / Water Temperature（水温）/ TDS / Turbidity（濁度）/ Water Level（水位） | IoTセンサーで3〜5分ごとに計測する水質モニタリング項目 |
| TAN / NO2 / Vibrio / Alkalinity | 週次の検査（Laboratory Results）で測定する項目 |
| 閾値超過アラート | Sensor Databaseの水質項目があらかじめ設定した閾値（Alert rule）を超えた場合に発報される Pond Alert |
| Actuator | ポンプ・エアレーター等、池の環境を物理的に制御する機器 |
| PID制御（Auto） | 目標値（DOなど）に対する自動制御。Actuatorの制御モード「Auto」 |
| Human Override（Manual） | 自動制御に対してTechnical Managerが手動で介入・上書きする操作。制御モード「Manual」 |
| Safety Layer | 自動制御や手動操作が誤っても安全を確保するための制御層。安全上の制約に反する操作を拒否する |

## 4. 生産

| 用語 | 定義 |
| --- | --- |
| 放養（Stocking） | 稚エビ（PL）を池に入れること。放養日・放養尾数を記録する |
| DOC（Days of Culture） | 放養日からの経過日数。Pondごとに異なる |
| 週次サンプリング | 週1回程度エビを採取して重量・尾数を測定する作業と、その記録 |
| ABW / ADG / Survival Rate / Biomass / FCR / Size Uniformity | 生産KPI（平均体重／日間成長量／推定生存率／推定生体量／飼料要求率／サイズの揃い）。算出式は「04_KPI・データ項目定義書」 |
| 目標成長曲線 | DOCごとの目標ABW。Pondの成長の良し悪しを判断する基準 |
| Growth vs target（目標比） | PondのABWが、同じDOCの目標ABWに対してどれだけ上回る／下回るか。On track / Behind / Ahead で示す |

## 5. 状態

| 用語 | 定義 |
| --- | --- |
| 重大度（Severity） | Normal（正常）< Attention（注意・確認推奨）< Warning（警告・対応が必要）< Critical（重大・即時対応が必要） |
| アラート状態 | アラートの対応状態。Unacknowledged（未確認）→ Acknowledged（確認済み）→ In Progress（対応中）→ Resolved（解決済み） |
| レポート状態 | Draft（下書き。Technical Managerのみ閲覧可）→ Submitted（提出済み。Farms Managerが閲覧可） |
| データ品質 | センサー値の鮮度。Live（最新）/ Delayed（更新遅延）/ Offline（通信断・センサー停止）/ No data（データなし） |
| アカウントの状態 | Invited（招待済み・パスワード未設定）/ Active（利用中）/ Deactivated（無効化。ログイン不可、記録は残る） |
| 機器の状態 | センサー・Actuatorの接続状態。Online / Offline / Unassigned（Pondに未割り当て） |
| Trend（傾向） | 値の変化の向き。↑ Increasing / ↓ Decreasing / → Stable。状態ではない |

## 6. 値の種類

| 用語 | 定義 |
| --- | --- |
| 実績値（Actual） | 実際に取得・入力・確定された値。予測値・推定値とは画面上で明確に区別する |
| 予測値（Forecast） | 将来の状態や数量をモデル・ルールにより算出した値。対象期間と予測であることを画面に表示する |
| 推定値（Estimated） | 直接観測できない状態を既存データから算出した値（例：Survival Rate、Biomass）。算出方法または根拠を確認できるようにする |
| 集約値 | 複数のPond・期間のデータを集計した値。合計または重み付きで算出し、単純平均はしない（「04_KPI・データ項目定義書」） |

## 7. Report と Alert の違い

「今何が起きているか」はSensor Data・Alertで、「何が起き、何を観察し、何をしたか」はReportで扱う。ReportはAlertの前提ではなく、Reportにセンサー値を手入力・転記しない。

| 項目 | Alert | Daily Report | Weekly Report |
| --- | --- | --- | --- |
| 主な目的 | 異常な状態を検知する（Detect abnormal condition） | その日の運用を記録する（Record today's operations） | 週の進捗をまとめる（Summarize weekly progress） |
| 情報源 | Sensor / System | TM + DB | DB + TM |
| 頻度 | 常時・イベント発生時 | 毎日 | 毎週 |
| センサー値 | システムが生成 | 参照のみ | 傾向（自動集計） |
| Feeding | — | あり | サマリー |
| Mortality | — | あり | サマリー |
| 健康状態の観察 | — | あり | サマリー |
| Equipment | — | あり | 主要な事象 |
| Actions | — | あり | 主要な対応 |
| Production | — | 限定的 | 主な焦点 |
| 人が書く所見 | — | あり | あり |
| Farms Manager | View | Review | Review |
| Technical Manager | Respond | Create・Submit | Create・Submit |
